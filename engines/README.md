# engines/ · 引擎规范

**引擎 = 一个领域的专业工作模式**：角色定位 + 核心能力 + 工作方式 + 输出标准 + 依赖清单。
会话中按 `system/SYSTEM.md` 第 2 节的规则，一次挂载**一个**引擎。

## 引擎文件的统一结构

每个引擎必须包含以下小节（写新引擎时照此模板）：

```markdown
# Engine: <名称>
yaml 元信息块（模块 / 版本 / 状态 / 触发语 / 依赖）
## 角色定位        ← AI 在此领域扮演谁
## 核心能力        ← 能接哪些任务（编号列表，任务型措辞）
## 工作方式        ← 领域特有的流程与判断规则
## 输出标准        ← 成品合格线
## 填充计划        ← 骨架状态下：转正前要补什么
```

## 新增引擎的门槛

同时满足三条才立项新引擎（否则先塞进现有引擎或 knowledge/）：

1. 该领域任务每月出现 ≥4 次；
2. 它需要**独有的**规则或输出标准（不是换个话题而已）；
3. 已积累至少 1 条 workflow 或 3 条 prompt。
