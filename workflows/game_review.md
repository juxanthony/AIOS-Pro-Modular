# Workflow: 赛后复盘（比赛 → 根因 → 下周一件事）

```yaml
模块: workflows/game_review.md
版本: 0.1
状态: 试运行
引擎: basketball
预计耗时: 赛后 24 小时内，15–20 分钟
```

## 触发条件

任何正式比赛或有价值的友赛之后（赢球也复盘 —— 赢球时的问题最容易被掩盖）。

## 输入

- 比分与过程描述（几段话即可）、技术统计（如有）
- 教练现场观察 3 条（赛中随手记）
- `knowledge/basketball/team_profile.md`（对照赛前部署）

## 步骤

1. **收集**（赛后 24h 内趁记忆新鲜）—— 把输入丢给 P-B-002。
2. **四象限** —— 进攻做得好 / 进攻待改进 / 防守做得好 / 防守待改进，每格 ≤3 条，全部写「行为」不写「态度」（「退防慢于对方推进」✅，「不够拼」❌）。
3. **根因** —— 对最痛的 1–2 条做 5 Whys：是技术缺口、决策阅读、体能，还是心理/规则理解？
4. **定「下周一件事」** —— 只选一个训练主题进下周计划（喂给 weekly_training_plan 第 1 步）。
5. **球员反馈** —— 每人一句「具体强项 + 一个改进点」，适龄、正面、点行为（化名/号码记录，RULES R5）。
6. **回填** —— 对手情报写回 team_profile；有效/失效的战术记一笔；复盘结论存入训练记录。

## 完成标准

产出恰好一个「下周一件事」+ 球员逐人一句反馈；对手情报已回填。

## 常见坑

- 复盘变成情绪总结（「今天没状态」）—— 四象限强制写行为。
- 列出 8 个问题然后全都想练 —— 一周只修一件事，修透。
- （其余实战后补）
