# Workflow: 开题报告（问题 → 框架 → 方法论 → Defence）

```yaml
模块: workflows/proposal_writing.md
版本: 0.1
状态: 试运行（Anthony 当前主线工作流，边用边校准）
引擎: research（成文阶段协同 writing）
预计耗时: 以「关」为单位推进，每关可拆成多次会话
```

## 触发条件

开题阶段的任何实质工作：打磨题目、写 proposal 章节、准备 defence。

## 输入

- `knowledge/phd/project_profile.md`（每次必读，接上次卡点）
- `knowledge/phd/literature/` 现有笔记
- 大学的 proposal 结构要求（`style_guide.md`；未入库前用默认三章结构）

## 步骤（六关，顺序推进、允许回滚）

1. **问题关** —— 用 P-R-004 打磨问题陈述：现象 → 研究问题 → 空白 → 为什么值得做／为什么是现在／为什么是我。
   ⤷ 产物：一页问题陈述 + 2–4 条 RQ（混合方法：标明哪条靠定量、哪条靠定性、在哪里整合）。
2. **文献关** —— 跑 `workflows/literature_review.md`，目标明确：为每一个「空白主张」挂上文献证据。
   ⤷ 产物：综述章节的论证骨架（不是全文）。
3. **框架关** —— 选定理论框架 + 画概念框架（变量/概念关系图，文字版即可）。
   ⤷ 检验：每条 RQ 都能在框架图上指出位置；指不出的，改 RQ 或改框架。
4. **方法关** —— 混合方法设计选型（convergent / explanatory / exploratory sequential）+ 理由；
   对象与抽样、工具、效度信度方案、分析计划、伦理事项（在职教师研究自身场域的利益冲突要正面处理）。
   ⤷ 产物：方法论章节骨架 + 一张「RQ ↔ 数据 ↔ 分析」对齐表。
5. **成文关** —— 挂 writing 引擎逐章成文（先骨架后文字，金字塔原理）；每章过 P-W-002 论证链检查。
6. **Defence 关** —— 生成模拟评审提问（≥15 题，按「问题价值/文献/方法/可行性」分组）+ 应答要点；幻灯结构。

## 完成标准

Proposal 全稿 + 对齐检查通过（题目—问题陈述—RQ—框架—方法一条线，无断链）+ defence 预演跑过一轮。

## 常见坑

- 空白主张没有文献背书，被一句「你确定没人做过？」击穿 —— 第 2 关必须闭环。
- RQ 与方法脱节（问的是过程，收的是问卷分数）—— 第 4 关的对齐表就是防这个。
- （其余边用边补）
