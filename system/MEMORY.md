# MEMORY.md · 记忆系统

```yaml
模块: system/MEMORY.md
版本: 1.0
状态: 正式
角色: 定义系统记什么、记在哪、怎么写入、何时清理
依赖: knowledge/personal/（记忆的物理存放地）
```

> 平台自带的「对话记忆」不可靠也不可迁移。AIOS Pro 的记忆是**文件**：
> 写进仓库的才算记住，没写进仓库的等于没发生。

---

## 1. 三层记忆架构

| 层 | 内容 | 存放位置 | 变更频率 |
|---|---|---|---|
| **L1 身份层** | 我是谁、五条主线、长期目标、偏好 | `system/IDENTITY.md` | 极低（人生阶段变化才改） |
| **L2 领域层** | 各领域的稳定事实：课标、课题档案、频道数据、球队资料 | `knowledge/<领域>/` | 低－中（里程碑时更新） |
| **L3 进行层** | 当前进行中的事：本学期进度、论文当前章节、本周训练重点 | `knowledge/personal/current.md` | 高（每周刷新） |

判断存放层级的口诀：**一年后还成立 → L1/L2；下个月就过期 → L3。**

## 2. 写入协议（AI 必须执行）

触发写入的三种情况：

1. **用户显式指令**：「记住 X」→ 立即写入对应层级文件，并复述写入位置确认。
2. **会话沉淀**：会话中确认了新的稳定事实（如「课题改题目了」「换教新年级」）→ 会话收尾时建议写入，经确认后执行。
3. **占位符补全**：用户提供了某个 `【待填写】` 的内容 → 直接替换占位符。

写入格式（L2/L3 内的条目）：

```markdown
- [2026-07-17] 条目内容（一句话，事实体，不带修饰）
```

写入纪律：

- 一条记忆一句话；长背景拆成多条或另建文件。
- 写入 = 编辑对应文件 + `CHANGELOG.md` 的 `[Unreleased]` 记一行（L3 的日常刷新可免记）。
- 冲突处理：新事实与旧记录矛盾时，**更新旧条目**并保留旧值备注（`原为 X，2026-07-17 更新`），而不是追加一条矛盾记录。

## 3. 读取协议

- 会话启动只读 L1（IDENTITY 已在启动序列中）。
- L2 由挂载的引擎按其依赖清单读取。
- L3（`knowledge/personal/current.md`）在任务涉及「当前进度/近期安排」时读取。
- 检索优先于通读：找特定事实用搜索，不要为一条信息读全库。

## 4. 遗忘与归档

记忆系统的敌人是**过期信息被当成现实**。

- 每周复盘（`checklists/weekly_review.md`）时刷新 L3：完成的划掉、过期的删除。
- 每学期/每季度把 L3 中已结束的事项移入 `knowledge/personal/archive/<年份>.md`。
- L2 文件顶部标注 `最后核对: <日期>`；超过 6 个月未核对的领域文件，引用时提醒「此资料可能过期」。

## 5. 隐私提醒

L3 与 `knowledge/personal/` 整体属于 RULES.md R5 定义的**私密层**。
若本仓库设为公开，这一层必须先剥离（方案见 `automation/README.md` 的私密层分离一节）。
